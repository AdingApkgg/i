# Bangumi 单账号双向同步

用户已授权按讨论方案实现：单账号 token、追番状态、逐集进度、评分和短评双向同步；首次同步必须先演练预览，不能直接覆盖。既有技术栈继续使用。本文件补充实现者的具体取舍，不增加生产部署或真实账号写入授权。

## 范围与入口

- 新增 `/anime`「番剧」和 `/dash/anime`「番剧 · Bangumi」，不覆盖旧 `/movie` 整页/手工条目，不自动猜测旧影视标题与 Bangumi ID 的对应关系。
- 前台仅展示已确认入库的公开收藏：封面、中日文名、放送日期、集数、状态、已看集数、个人评分、短评、Bangumi 原条目链接。支持五种状态筛选。私有收藏不进入公开 RPC、SSR、前台或共享缓存。
- 后台支持通过数字 ID / bgm.tv、bangumi.tv、chii.in 的条目 URL 添加；编辑状态、0–10 分（0 清除评分）、短评、隐私与每集四种标记（未看/想看/看过/抛弃）。章节 ID 为主键，保留 SP/小数序号等，不把集数当 ID。
- 首版不做站内收藏删除、Bangumi 删除或自动传播删除；远端取消收藏进入冲突，由管理员选择重新收藏或保留本站且暂停该条目同步，绝不静默重建。

## Token 与 API

- `BANGUMI_ACCESS_TOKEN` 只通过服务端环境注入；不存数据库、不回传前端、不打印，不提供浏览器直连。后台显示是否配置、已验证账号、最近同步/错误与运行进度。
- API 固定 `https://api.bgm.tv`，Bearer token、标识项目的 User-Agent；不接收客户端任意 API 地址。测试通过服务端依赖注入 fetch，不能提供生产可配置的任意地址以免 token 外泄。
- `GET /v0/me` 验证账号。持久化数字账号 ID；更换 token 仍须匹配原账号，换账号需另行处理，禁止自动混合两个账号的数据。
- `GET /v0/users/{username}/collections?subject_type=2` 分页读取完整动画收藏；每条读取完整章节收藏。任一分页失败/结构异常时不生成可执行计划，不能把失败视为删除。
- 收藏新增 POST / 已有 PATCH `/v0/users/-/collections/{id}`，只发改变的 type/rate/comment/private。逐集进度走章节 API，绝不通过收藏的 ep_status 写动画进度。未编辑 tags 保持原样。
- 请求超时与 429/5xx 有界重试；状态变更使用幂等绝对值，无自动删除。401/403 清晰提示 token/权限问题；错误只包含操作与 HTTP 状态，不包含响应全文或 token。

## 数据与合并

- 新增独立 BangumiAccount、BangumiEntry、BangumiRun 表，不修改旧内容表；迁移为纯增量。
- Entry 保存条目资料、章节资料、本地收藏快照、上次双方一致的 baseline、revision、同步状态/错误。同步快照为 `{type,rate,comment,private,episodes: Record<episodeId, type>}`。
- 按每个普通字段和每个 episode ID 三方合并：只有本站变则推送；只有远端变则拉取；两边同值则确认；同一字段双方改成不同值则冲突。未受冲突影响的计划也先展示，冲突未解决不得确认整次演练。
- 无 baseline 的双边差异一律冲突；远端独有为导入、本站独有为新增收藏。任何预览都不改 Entry/baseline、不对 Bangumi 发写请求。预览内容可保存在 Run 的私有 JSON 中。
- 不依赖收藏 updated_at 作为增量游标：官方提示评分/短评/章节变化可能不更新它。用内容比较，完整枚举收藏；章节新增作为未看，不误判为用户修改。
- 冲突选择按字段指定「本站」或「Bangumi」；远端已取消的条目可选择「重新收藏」或「保留本站并暂停同步」。暂停条目仍可在后台管理，但定时同步不重建，管理员可通过新的演练重新启用。

## 首次演练与确认

1. 管理员点「演练预览」创建异步 Run，返回 ID，后台轮询显示扫描进度；没有 token 显示配置说明，不发写请求。
2. 完整扫描后展示条目、每字段前后值、方向、冲突和总计。Run 绑定账号 ID、本站 revisions 和远端快照，30 分钟过期。
3. 管理员明确点击「确认应用此预览」并提供冲突选择。服务端重新读取当前账号、全部相关远端状态与本站 revisions；任一变化则拒绝旧预览并要求重新演练，在任何写入前完成此检查。
4. 执行期间每条目再次检查远端，本站行锁防止同条编辑穿插；外部服务没有条件写接口，最后一次读取与请求之间的外部并发无法完全排除，应在运行记录中保留前后快照，并在写后回读核对。
5. 每条成功即保存一致 baseline；部分失败保留成功记录和待处理错误，不谎称跨站事务原子性，不标整次成功。首次确认完整成功后才标 initialized；自动同步开关默认关闭，由管理员明确开启。

## 后续同步与任务互斥

- initialized 后站内编辑先保存本地 pending，再唤醒同步任务；同步失败不丢编辑。未 initialized 时只保存本地，仍必须演练后确认。
- 后续「立即同步」与每 10 分钟自动同步均三方合并；有冲突的条目不写入，进入后台解决。其余条目可同步。所有写入都按 baseline 检查远端，避免盲目把本地重发。
- 数据库账号行保存 activeRunId，通过事务/条件更新使同一时刻仅一个任务运行；任务固定 15 分钟执行上限，每个请求有超时。进程重启/超时的任务可在超过上限后标失败并释放，重复提交同一确认不会产生重复执行。
- 本地编辑与每条同步通过数据库行锁串行，revision 校验拒绝过期表单。只读扫描不锁住编辑；正式应用前的预检查拒绝扫描期间变化。
- 没 token、没激活、自动同步关闭或 DISABLE_SCHEDULERS=1 时不会自动写入。后台手动操作仍可演练/确认。

## 验证与交付

- Mac 只读改和 Git；Bun 1.4.3 安装、迁移生成、lint、typecheck、Vitest、构建、Chromium 全部在 localhost-1。现有开发库先备份，再仅应用增量迁移；不重置/seed 真实内容副本。
- 先测纯合并器，再测真实 PGlite 迁移/路由/服务；外部 Bangumi 使用协议级 fake fetch，不 mock 合并/数据库。覆盖首次零写、确认/过期/重复/数据变化、冲突、分页异常、隐私、账号切换、部分失败、重试、逐集 ID 与权限。
- 浏览器用隔离服务端 Bangumi 测试替身（只存在测试脚本），覆盖后台演练→确认→编辑→双向更新→冲突→前台隐私过滤。完整站点 CI 使用独立 Docker 生产栈。
- 真实 token 未提供时，清楚区分接口模拟验收和真实账号验收；真实账号首次演练可只读执行，任何实际写入仍需用户审阅真实预览后明确确认。
- 本次创建独立 PR 并等待 CI；不自动合并、不部署 arch。
